# [내부·기획] 직원정보관리 UX 시나리오 (260823)

## 결론

- 인사담당자 업무는 3사이클 — **① 일상 조회 ② 이벤트 처리(입사·발령·휴직·퇴사) ③ 정기 집계**
- 시스템 솔루션 3축 — **검색·필터 목록 / 상태변경 시 이력 자동기록 / 현황 대시보드**
- 오늘 테스트 시나리오 8건 (아래 §4) · MVP 요구사항 10건 (아래 §5)
- 판단 요청: 시나리오 S1~S8 중 데모에서 보여줄 순서 확정

---

## 1. 페르소나

- 인사팀 담당자 (140명 규모, 실무자 1~2명)
- 현재 도구: 엑셀 인사기록카드 (1행 = 1인, 186컬럼)
- 목표: 직원 정보를 한 화면에서 조회·변경·집계

## 2. AS-IS → Pain Point

| 사이클 | AS-IS | Pain Point |
|---|---|---|
| ① 일상 조회 | 엑셀에서 Ctrl+F 검색 | 186컬럼 수평 구조 > 1명 정보 파악에 좌우 스크롤 > 조회 자체가 노동 |
| ① 일상 조회 | 부서·상태별 보기 = 매번 필터 재설정 | 조건 조합 조회 불가에 가까움 |
| ② 이벤트 처리 | 입사·퇴사 시 셀 직접 수정 | 언제·무엇이 바뀌었는지 이력 없음 > 소급 확인 불가 |
| ② 이벤트 처리 | 상태(재직/휴직/퇴사)와 일자를 따로 수정 | 퇴사인데 퇴사일 공란 등 정합성 깨짐 |
| ③ 정기 집계 | 인원현황 시트 수식 (#REF! 다수) | 원본 구조 변경 시 집계 붕괴 > 매월 수작업 재집계 |
| 공통 | 파일 공유 방식 | 최신본 불명확 · 개인정보 파일이 메일·메신저로 유통 |

## 3. 개선 목표 → TO-BE 솔루션

| 목표 | 솔루션 | 화면 |
|---|---|---|
| 1명 정보를 한 화면에 | 직원 상세 뷰 + 발령이력 타임라인 | 상세 |
| 조건 조회를 3초 안에 | 이름 검색 + 소속·부서·재직구분·직급 필터 | 목록 |
| 변경은 반드시 이력으로 | 상태변경·발령 시 이력 자동 생성 (수기 기록 제거) | 상세/변경 모달 |
| 정합성 시스템이 보장 | 퇴사 처리 시 퇴사일 필수 · 상태-일자 연동 검증 | 변경 모달 |
| 집계 0초 | 재직구분·부서별 인원 자동 카운트 | 대시보드 |

## 4. 테스트 시나리오 (오늘 데모)

> 형식: 행동 → 기대 결과. 더미데이터 158명(재직 136 · 휴직 4 · 퇴사 18 — 현원 140명 규모) 기준



### ① 일상 조회

- **S1 아침 현황 파악** — 대시보드 진입 → 총원 158 · 현원 141(재직 136 + 휴직 4 + 퇴사예정 1) · 퇴사 17, 부서별 인원 표시 (최다 제작 1팀 25)
  - 퇴사예정 = 퇴사일이 미래인 직원. DB에는 '퇴사'로 저장, 표시 계층에서 오늘 날짜와 비교해 자동 구분 (일자 도래 시 자동 전환)
- **S2 직원 검색** — 목록에서 이름 일부 입력 → 즉시 필터링 → 클릭 시 상세 진입
- **S3 조건 필터** — 소속 '가온플러스' + 재직구분 '재직' 선택 → 53명 표시, 건수 일치
- **S4 상세 조회** — 임의 직원 클릭 → 기본정보 13항목 + 발령이력 시간순 표시

### ② 이벤트 처리

- **S5 신규 입사 등록** — 등록 폼 작성·저장 → 목록에 159번째 직원 + '입사' 발령이력 자동 생성
- **S6 부서 이동** — 재직자 1명 부서 변경 → 상세 반영 + '발령' 이력 자동 생성
- **S7 휴직 처리** — 재직자 1명 상태 '휴직' 변경 → 대시보드 휴직 5로 증가 + 이력 생성
- **S8 퇴사 처리** — 재직자 1명 퇴사 처리 → 퇴사일 입력 필수(미입력 시 저장 차단) → 상태·이력·대시보드 동시 반영

### 엣지 검증 (시간 남으면)

- 퇴사일이 입사일보다 앞서면 저장 차단
- 퇴사자 정보 수정 시도 → 허용 범위 확인 (연락처만? 전체?)
